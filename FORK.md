# Hermes Engineering Team — личная ветка разработки

Это форк [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent),
в котором собраны доработки доски и конвейера команды, ранее хранившиеся в
локальном пакете и в рабочей копии Hermes на сервере.

Ветка разработки: **`codex/engineering-team-flow`**. База совместимости:
**`codex/hermes-deployed-base`**, commit
`5cc1369fa298021f8c740de154ff8c37c30bdcc8` (Hermes 0.20.6).
`main` форка сохраняет upstream. Эта ветка не является переносом на новейшую
версию Hermes: обновление базы требует отдельного сравнения API и регрессии.

## Что включено

| Часть | Где искать | Изменения |
| --- | --- | --- |
| Основной интерфейс | `web/src/` | Русский интерфейс, словари, подписи, выбор моделей и общий вид страниц. Английский остаётся доступным. |
| Нативная доска | `plugins/kanban/dashboard/dist/` | Читаемые карточки, причины ожиданий и остановок, подробности запусков, обзор каталога проекта. |
| Командная панель | `contrib/hermes-team/dashboard/` | Задачи, роли, модели, квоты, проекты, вложения и согласования. Тема находится в `dashboard/themes/`. |
| Оркестратор | `contrib/hermes-team/team_engine/` | Анализ → требования → план → skeptic/test-designer/judge → реализация → review/QA → интеграция/регрессия → приёмка. |
| Роли и контракты | `contrib/hermes-team/roles/`, `templates/`, `skills/` | 13 профилей, структурированные отчёты и проверки согласованного snapshot. |
| Квоты и доступ | `agent/account_usage.py`, `agent/credential_pool.py`, `hermes_cli/auth.py`, командный пакет | Проценты Anthropic, общий OAuth pool только для явно помеченных team-профилей, admission по квотам. |
| Нативные workers | `hermes_cli/kanban_db.py`, `hermes_cli/kanban_decompose.py` | Удаление унаследованных credential-переменных, сохранение управляемых блокировок и исключение этих карточек из auto-decomposition. |
| Ожидание тестов | `agent/turn_context.py`, `agent/turn_finalizer.py`, командный пакет | Долгие проверки отдельными заданиями, освобождение worker, накопительный бюджет и ограниченные попытки восстановления. |
| Доверенные проверки | `contrib/hermes-team/scripts/`, `team_engine/check_jobs.py`, `team_engine/backend_test_jobs.py` | Очереди, привязка к SHA, дедупликация, sandbox/host bridge, rootless backend tests и изолированный demo walkthrough. |

Семантика согласований сохранена: требования и итог принимает владелец;
согласование плана требуется по умолчанию. Контроллер не получает права
сливать защищённые ветки или выпускать production.

## Как пользоваться исходниками

Начните с [пакета команды](contrib/hermes-team/README.md) и
[инструкции экспорта и установки](contrib/hermes-team/docs/FORK-EXPORT.md).
`SOURCE-MANIFEST.json` в пакете содержит SHA-256 включённых исходников и их
происхождение; это позволяет проверить полноту переноса.

Изменения React и встроенных плагинов уже находятся на своих местах в форке.
Повторно применять архивные `dashboard/patches/*.patch` к этой ветке не нужно.
Командный пакет устанавливается отдельно в `<Hermes root>/team/runtime`;
его Python-модули нужны нативным hooks при работе Kanban workers.

Установочные wrappers и host test adapters сохраняют существующую Linux-схему
развёртывания. Они содержат фиксированные пути и allowlist тестового проекта;
это исходники работающей интеграции, а не универсальный установщик для любого
пользователя. Сначала проверьте пути, контейнер, права и изоляцию в отдельной
копии. Не запускайте `bootstrap.py` или старые hardening-патчеры автоматически.

## Проверки и границы

Актуальные результаты экспорта указаны в
[FORK-EXPORT.md](contrib/hermes-team/docs/FORK-EXPORT.md).
Исторические записи установки не заменяют повторный live E2E на новой машине.
Этот перенос не запускает моделей, не восстанавливает старые задания и не
меняет установку на сервере.

В Git не включены credentials, персональные конфигурации, базы доски,
промпты/журналы запусков, runtime state, резервные копии, снимки CRM и исходные
бизнес-документы. Исправления разовых инцидентов включены в виде конечного
кода и regression-тестов; скрипты изменения конкретных исторических карточек
не являются частью поставки.

## Дальнейшая разработка

Ветки с улучшениями создавайте от `codex/engineering-team-flow`, а PR направляйте
в неё же в `Violine/hermes-agent`. Не используйте `hermes update` для замены этой
ветки свежим upstream без отдельного переноса и проверки командных hooks.
Обновление upstream, установка на сервер и возможная отправка отдельных
улучшений в NousResearch — самостоятельные операции после review.
