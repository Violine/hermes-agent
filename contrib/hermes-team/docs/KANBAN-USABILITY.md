# Читаемая доска и причины ожидания

Доработка веб-плагина Kanban для установленного Hermes 0.20.6. Работающий интерфейс берётся из `plugins/kanban/dashboard/dist/`, это самостоятельный JS без сборки. Desktop-компоненты `apps/desktop/src/plugins/kanban` эту страницу не обслуживают.

## Поведение

- По умолчанию показаны непустые колонки текущей работы. Переключатель «История» возвращает завершённые задачи, «Вид и фильтры → Все этапы» — в том числе пустые колонки. Поиск и фильтры ищут также среди завершённых задач; архив включается отдельно. Счётчик сообщает число показанных и общее число задач после фильтрации.
- На карточке видны понятное имя исполнителя и краткое состояние. Повторяющийся префикс `[req-…]` убран только из отображения. В базе название и ID сохранены.
- Открытая карточка начинается с исполнителя, ссылки на запрос команды, причины ожидания и следующего действия. Квота на одновременные запуски, недоступный ресурс модели, незавершённые зависимости, согласование владельца, ошибка запуска и ожидание допуска оркестратора различаются.
- В сводке используются текущие назначения команды, статусы родителей и последние нативные запуски. Текст задания и произвольные комментарии не считаются доказательством причины блокировки. Если данных нет, интерфейс прямо сообщает об этом.
- Длинные отчёты и комментарии имеют короткое превью; полный текст раскрывается отдельно. Видны последние три комментария, более старые доступны в раскрываемом блоке. Инструкция агенту, данные задачи, изменение статуса, зависимости, события и журналы находятся в закрытых «Технических подробностях».
- Шрифты и межбуквенные интервалы нормализованы в пределах Kanban независимо от текущей темы. Для кода и журналов сохранён моноширинный шрифт.

Интерфейс не разблокирует задачи, не завершает проверки и не меняет ограничения подписки. Согласования требований, плана и результата выполняются в запросе «Команды»; ссылка из карточки ведёт туда.

Если контроллер остановил весь запрос (`stage=blocked`) и записал причину, карточка показывает техническую остановку процесса. Непринятый QA-отчёт отображается как «Не принят отчёт проверки»; это само по себе не означает дефект кода или вопрос владельцу. Запланированные карточки показывают «Ожидает возобновления команды». Устаревшее ожидание квоты не перекрывает эту остановку; подробный машинный JSON остаётся в запросе.

## Источники и установка

- `dashboard/kanban/index.js`, `style.css` — точные опубликованные файлы плагина.
- `dashboard/operator-status.js` — канонический чистый helper. Он встроен между маркерами `BEGIN/END operator-status.js` в опубликованный JS. При правке helper нужно синхронизировать этот фрагмент; тест проверяет равенство.
- `dashboard/patches/hermes-0.20.6-kanban-usability.patch` — diff относительно уже установленной русификации и выбора серверной папки. Это дополнительный patch, а не замена предыдущих.

Для повторной установки на совместимом checkout сначала выполнить `git apply --check` дополнительного patch. Полные файлы можно копировать только после сверки версии и существующих изменений: слепая замена способна затереть последующие доработки. Обновление этих JS/CSS не требует сборки Vite или перезапуска gateway/воркеров; браузеру нужна перезагрузка страницы.

Снимок команды загружается одним запросом вместе с доской. Для причин блокировки дополнительно читаются детали только ожидающих задач, максимум четыре запроса одновременно. Они кэшируются на минуту, сбрасываются при событиях соответствующей задачи и ручном обновлении. Обновление состояния команды раз в 30 секунд страхует отсутствие событий о смене назначения. Ошибка необязательного API не подменяет причину догадкой.

## Проверки и откат

```sh
node --check dashboard/kanban/index.js
node tests/test_kanban_operator_status.cjs
node tests/test_kanban_usability_ui.cjs
node tests/test_dashboard_workflow_ui.cjs
node tests/test_dashboard_attachments_ui.cjs
```

Первый набор проверяет достоверность причин и приоритет текущего состояния над старыми ошибками. Второй проверяет начальный вид карточки, закрытые подробности, доступность истории, счётчик, отсутствие изменения исходных данных и ограничение/кэширование запросов диагностики.

Резервная копия исходных файлов на сервере:

a verified backup made for the target installation

Для отката вернуть оттуда только `index.js` и `style.css` в каталоге собранных assets Kanban соответствующей установки и обновить страницу. Database contents, credentials, network configuration, and application data are outside this UI update.
