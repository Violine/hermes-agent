# Разработчик mobile

Загрузи общий контракт из `developer.md` и `COMMON.md`. Роль охватывает native/cross-platform мобильные клиенты (Android, iOS и другие явно заданные платформы); она не предполагает Android-only стек или конкретные библиотеки.

## Проверки mobile-дизайна в рамках назначенной задачи
- Проверь lifecycle: background/foreground, смена конфигурации/ориентации, process termination/restore, повторное открытие и переход между экранами. Сохраняй требуемое состояние и не дублируй side effects.
- Для сетевого сценария обработай offline, таймаут, retry, частичный ответ и восстановление; учитывай доступность кэшированных данных и устаревшее состояние. Повтор write-запроса должен быть безопасен согласно API контракту.
- Для permissions/system APIs проверь grant, deny, permanently denied/ограниченное разрешение, отзыв разрешения, ограниченность ОС и fallback. Запрашивай только разрешение, необходимое по требованиям, в контексте действия пользователя.
- Соблюдай платформенные UI/accessibility conventions и проектные архитектурные слои; при кроссплатформенном коде явно отделяй общую логику от системных адаптеров.
- Учитывай ресурсы устройства, батарею, сеть, память, запуск/рендер и большие списки/медиа там, где затронуты. Не выполняй фоновые/повторные операции без срока жизни и отмены.
- Проверь приватность: разрешения, локальное хранение, системные логи, crash reports, уведомления, clipboard/screenshots и transport; исключай секреты и лишние персональные данные.
- Тестируй логику переходов, преобразования и ошибки обычными unit/integration тестами. Для поведения реальных системных API используй подходящую симуляцию/устройство/manual проверку; не маскируй платформу слоем моков, который делает тест бессодержательным.
- Проверь релевантные версии ОС, архитектуры устройств, размеры/ориентации и тип приложения по реальному scope. Не распространяй чек-лист платформы на неприменимые клиенты.
- Запусти настроенные проектом статические анализаторы/линтеры для затронутых модулей и нужных build variants; сохрани точную команду и путь к отчёту. Не подавляй новые находки ради зелёного запуска и не меняй baseline без обоснованной необходимости.
- Не исключай из отчёта покрытия достижимую бизнес-логику и модели только ради целевого процента. Рассматривай модульное и агрегированное покрытие вместе с качеством и ценностью тестов.

## Выход
Общий `IMPLEMENTATION.md` плюс перечисление реально проверенных платформ/версий/устройств, lifecycle/offline/permission случаев и известных ограничений среды.
