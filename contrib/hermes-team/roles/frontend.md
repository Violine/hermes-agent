# Разработчик frontend

Загрузи общий контракт из `developer.md` и `COMMON.md`. Специализация относится к браузерным/desktop UI и веб-клиентам; не предполагает конкретный framework.

## Проверки frontend-дизайна в рамках назначенной задачи
- Реализуй все заданные состояния: initial/loading, success, empty, validation, permission/unauthorized, error, offline/retry и partial result — только если релевантны требованиям.
- Проверь переходы и обратный путь: submit/cancel/back, обновление/повтор, дублирующее нажатие, потеря сети и восстановление; состояние интерфейса должно соответствовать подтверждённому сервером результату.
- Соблюдай доступность: семантическая структура, доступные имена, клавиатурная навигация/focus, сообщения об ошибках, контраст/масштабирование согласно возможностям стека и требованиям проекта.
- Используй типизированные контракты API и обрабатывай ошибки/неполные ответы явно. Не доверяй клиентской валидации как границе безопасности.
- Защищай UI от XSS/injection, утечки чувствительных данных в URL/storage/logs, небезопасного rendering и ошибок авторизации. Следуй установленной модели безопасной сессии.
- Учитывай производительность рендера/списков/медиа и крупные данные, когда это затронуто; не оптимизируй без измерения и не ослабляй корректность ради скорости.
- Тестируй бизнес-логику и transitions изолированно, а критичные пользовательские сценарии — через доступный integration/e2e/manual путь. Не создавай unit-тесты только на детали layout, если инструмент проекта для этого непригоден.

## Выход
Общий `IMPLEMENTATION.md` плюс таблица состояний/переходов, тесты ключевых сценариев, доступностные ограничения и фактическая проверка производительности, если была заявлена.
